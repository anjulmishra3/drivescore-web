# analysis — offline sensor experiments

Scratch space for working with a drive's raw sensor stream in Python/Jupyter.
Nothing here runs in the app; it reads the DB (or a CSV) directly.

## Gyro / mount calibration

Recovers the phone→vehicle rotation from one drive and transforms accel+gyro into
the vehicle frame (longitudinal / lateral / vertical + true yaw rate). See
`gyro_calibration.ipynb`. Method: gyro bias from stationary samples → up axis from
gravity → forward axis from GPS-correlated longitudinal accel → rotate + validate
against GPS heading-rate. Validated on synthetic data (recovers a known mount
rotation; yaw-vs-GPS correlation ~1.0).

### 1. Get the drive CSV

Default drive: `4941031e-…` (2026-11-01 09:41 UTC, first drive, has labels).

**Option A — script** (needs the DB string in `../map/.db_url` or `DB_URL` env,
same as the map pipeline):

```bash
python3 analysis/dump_drive.py                 # default drive
python3 analysis/dump_drive.py <trip_uuid>     # another drive
```

Writes `analysis/data/trip_<id>.csv` (+ `_labels.csv`).

**Option B — no DB setup:** in the Supabase SQL editor, run and "Download CSV":

```sql
select seq,t_ms,speed_kmh,accel_x,accel_y,accel_z,gyro_alpha,gyro_beta,gyro_gamma,lat,lng
from trip_samples where trip_id = '4941031e-df94-4caf-ab4c-f821e1b8b9fd' order by seq;
```

Save it as `analysis/data/trip_4941031e-df94-4caf-ab4c-f821e1b8b9fd.csv`.

### 2. Run the notebook

```bash
pip install jupyterlab          # if not installed; or open in VS Code
jupyter lab analysis/gyro_calibration.ipynb
```

`gyro_calibration.ipynb` is generated by `build_notebook.py` (edit there, re-run
`python3 analysis/build_notebook.py`, so the JSON stays valid).

Data CSVs are git-ignored.
